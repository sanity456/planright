Title
EntitlementVersionJoin - Versioned Feature Mask Resolver

Notes / Description
Built EntitlementVersionJoin, a reusable feature catalog and time-bounded plan-version registry where validators map a capability request to one feature and code joins frozen base, add-on, and grandfathered masks. Its distinct GenLayer-native mechanism is versioned catalog snapshot -> semantic feature identifier -> deterministic three-mask entitlement join. Correction applied: Feature resolution now uses the same catalog-bound feature canonicalizer in the validator and after consensus; a merely well-shaped but catalog-invalid leader result is rejected. The full selected set was checked against both steward findings: substantive leader payloads must bind every derived digest, mask, and state field, while operational registries must be owner-scoped or safely reclaimable. No live source collection. Catalogs, versions, subscription masks, and references are public provider declarations and are not authenticated. It does not grant product access, authenticate a provider, bill add-ons, or replace an authoritative entitlement system. GenVM lint and strict typecheck pass; 11 direct tests and 1 five-validator GLSim integration test pass. A fresh repository-specific external wallet set was used, with no workspace, other-owner, or cross-repository wallet reuse. The StudioNet workflow finalized successfully in 5 transactions. The deployed source was read back byte-for-byte, the complete deployed schema matched abi.json exactly, and mechanism-specific terminal state was read back. The current release is commit a7cb01e16601fba79ac5d77df71be98b60243902; contract source: https://github.com/sanity456/planright/blob/a7cb01e16601fba79ac5d77df71be98b60243902/contracts/entitlement_version_join.py.
